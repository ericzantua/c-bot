# C-Bot — Costco Product RAG Chatbot 🛒🤖

Ask questions about, or compare, Costco products by **text**, **voice**, or
**photo**. Product data is scraped from costco.ca by item code, embedded locally,
and stored in a persistent vector database. Answers are generated by Claude,
grounded only in the retrieved product data.

- **Backend:** Python + FastAPI, ChromaDB, sentence-transformers, Playwright
- **Frontend:** React (Vite), Web Speech API for wake-word voice + text-to-speech
- **LLM:** Claude (`claude-sonnet-4-6`) for chat and vision (item-code extraction)

---

## Features

| Feature | How |
| --- | --- |
| **Index by item code** | Sidebar → paste one or more codes → scrape → embed → store |
| **Index by photo** | Upload a price tag / shelf label → Claude vision reads the item numbers → same pipeline |
| **On-demand ingestion** | Ask about a product that isn't indexed; C-Bot asks for its item code |
| **RAG chat** | Ask about one product or compare several; answers cite the products used |
| **Voice ("C-Bot")** | Wake word "C-bot" (say "see-bot"), chime, speech-to-text, spoken replies, animated character |
| **Graceful degradation** | Full text chat works with no mic / unsupported browser |

## Prerequisites

- **Python 3.11–3.13** recommended. ⚠️ Very new interpreters (e.g. 3.14) may not
  yet have prebuilt wheels for `torch` (a `sentence-transformers` dependency),
  `chromadb`, or `playwright`. If `pip install` fails to build a wheel, use a
  3.11–3.13 virtual environment (e.g. `python3.12 -m venv .venv`).
- **Node.js 18+** and npm.
- An **Anthropic API key**.

## 1. Backend setup

```bash
cd backend

# Create and activate a virtual environment (use 3.11–3.13 if 3.14 fails)
python3 -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate

pip install -r requirements.txt

# Install the headless Chromium that Playwright drives
playwright install chromium

# Configure your API key
cp .env.example .env
# then edit .env and set ANTHROPIC_API_KEY=sk-ant-...
```

Run the API (http://localhost:8000):

```bash
uvicorn main:app --reload --port 8000
```

Quick check: `curl http://localhost:8000/health` → `{"status":"ok","products":0}`.

The first chat/index call downloads the `all-MiniLM-L6-v2` embedding model
(~90 MB, one time). ChromaDB persists to `backend/chroma_db/`, so indexed
products survive restarts.

## 2. Frontend setup

```bash
cd frontend
npm install
npm run dev
```

Open **http://localhost:5173**. The dev server proxies `/api/*` to the backend
on port 8000 (see `vite.config.js`), so no CORS setup is needed for local dev.

> **Voice note:** wake-word listening and speech-to-text use the browser's Web
> Speech API, best supported in **Chrome/Edge**. Firefox/Safari may lack
> recognition — text chat still works fully. The mic requires HTTPS or
> `localhost` and a permission grant.

## 3. End-to-end test

With both servers running:

1. In the sidebar click **Load sample products** (seeds mock products without
   scraping — the most reliable way to try the app).
2. Ask in the chat: *"Compare the air purifier and the fan."* — the answer cites
   the products it used.
3. Ask about something not indexed: *"Tell me about item 9999999."* — C-Bot
   flags it as not found and asks for the item code.
4. Turn on the mic, say **"C-Bot, what's the cheapest option?"**, and the reply
   is read aloud while the character animates.

For **real** Costco data, see the next section — costco.ca actively blocks
automated scraping, so the reliable path is the CDP "open tabs" workflow.

## Getting real Costco data (past bot detection)

costco.ca is behind Akamai bot management. It blocks any page the app
**navigates to** (HTTP 403), even with a real, visible Chrome from a home IP —
but it does **not** block a page **you** open by hand. So the reliable path is to
browse to products yourself and have the app read your already-open tabs.

**One-time setup (macOS):**

1. Quit Chrome (⌘Q), then start it with remote debugging on a dedicated profile:
   ```bash
   "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
     --remote-debugging-port=9222 --user-data-dir="$HOME/.costco-chrome" \
     > /dev/null 2>&1 &
   ```
2. In `backend/.env`, set:
   ```
   CDP_URL=http://localhost:9222
   ```
3. Restart the backend so it picks up `CDP_URL`.

**Each time you want to ingest products:**

1. In that debug Chrome window, browse to the Costco product page(s) you want.
   Clear any "press & hold" / challenge so each product renders normally.
2. In the app sidebar, click **Read open Costco tab(s)**. The backend connects to
   your Chrome over CDP, reads each open product tab's DOM (no navigation), and
   indexes it. Then chat about them.

**Other ingestion methods** (all in the sidebar):

| Method | When to use |
| --- | --- |
| **Read open Costco tab(s)** | Recommended for real data — reads your hand-opened tabs via CDP |
| **Add by product URL** | Paste full `…/p/-/<slug>/<partNumber>…` URL — works only where automated nav isn't blocked |
| **Add by item code** | `/index` scrape by item number — usually 403s (Costco blocks it) |
| **Add by photo** | Upload a price tag / shelf label; Claude vision reads the item number |
| **Load sample products** | Mock data for local testing, no network |

> Scraper stealth flags (`STEALTH_MODE`, `HEADLESS`, `CHROME_CHANNEL`,
> `USER_DATA_DIR`) exist for the automated paths, but on a blocked network only
> the CDP open-tabs path reliably works. Respect Costco's ToS; keep volume low.

## API reference

| Method | Path | Body / params | Purpose |
| --- | --- | --- | --- |
| `POST` | `/index` | `{ item_codes: string[] }` | Scrape by item code → chunk → embed → store |
| `POST` | `/index/url` | `{ urls: string[] }` | Scrape by full product URL |
| `POST` | `/index/open-tabs` | — | Read + index Costco tabs open in the CDP Chrome |
| `POST` | `/index/manual` | `{ products: ProductData[] }` | Index supplied data (no scrape) |
| `POST` | `/index/mock` | — | Load bundled sample products |
| `POST` | `/index/photo` | multipart `image` | Vision extracts codes → same pipeline |
| `POST` | `/chat` | `{ question, history[] }` | RAG answer + citations + `product_not_found` |
| `GET` | `/products` | — | List indexed products |
| `DELETE` | `/products/{item_code}` | — | Remove a product |
| `GET` | `/health` | — | Liveness + product count |

## How grounding & "not found" work

`rag.py` retrieves the top-k relevant chunks from ChromaDB and passes them to
Claude with a system prompt that forbids outside knowledge. If the asked-about
product isn't in the retrieved context, Claude emits a `[PRODUCT_NOT_FOUND]`
marker; the backend strips it, sets `product_not_found: true`, and the UI
prompts the user for the item code (feature 1c).

## Security notes

- The Anthropic API key lives only in `backend/.env` (git-ignored) — never in
  the frontend or source.
- Uploaded photos are sent to Claude for item-number extraction only; avoid
  uploading images containing personal or sensitive information.
